One correction to the proposed chunk model

I would not make ChunkDynamicState itself immutable while also giving it a mutable dirty property:

interface ChunkDynamicState {
  readonly ...
  dirty: boolean;
}

That’s internally contradictory.

Instead, make the live ChunkStore own mutable residency/mutation state, while snapshots contain immutable copies.

Conceptually:

LIVE WORLD
ChunkStore
 ├─ ChunkRecord
 │   ├─ geometry
 │   ├─ dynamicState
 │   ├─ residency
 │   └─ dirty

 └─ WorldEntityRegistry
          ↓
     snapshot barrier
          ↓
IMMUTABLE SIMULATION
ResidentGeometrySnapshot
          ↓
TileQueryFn
          ↓
GameState

That keeps the async/live side and deterministic/snapshot side very cleanly separated.
