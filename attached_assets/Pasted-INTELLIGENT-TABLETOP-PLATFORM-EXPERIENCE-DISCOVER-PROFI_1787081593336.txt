INTELLIGENT TABLETOP — PLATFORM EXPERIENCE, DISCOVER, PROFILE & TITLE SYSTEM

Repository:
JerichoOmega/tabletop-platform

This is a product-level architecture and UX directive.

We have now established several foundational decisions about what Intelligent Tabletop is as a platform.

The repository already contains:

- Canonical visual asset library
- Grand Gaming Table V1
- Authoritative WorldBounds
- Core tabletop/camera direction documentation
- Existing gameplay/world architecture

Do NOT undo or redesign any of that work.

This task is to incorporate the newly established platform philosophy into the project's architecture and documentation, and determine the appropriate implementation path.

Do not launch into a large unrelated UI rewrite unless specifically required by the existing milestone plan.

==================================================
1. INTELLIGENT TABLETOP IS A TABLETOP GAMING PLATFORM
==================================================

The most important product-level clarification is:

INTELLIGENT TABLETOP IS NOT AN AI D&D GAME.

It is a platform for many different types of tabletop experiences.

Examples include:

- RPGs
- Tactical RPGs
- Card games
- Board games
- Strategy games
- Risk-style grand strategy games
- Monopoly-style economic games
- War games
- Party games
- Cooperative games
- Competitive games
- Puzzle games
- Future tabletop game types not yet defined

The RPG/tabletop-dungeon experience currently being developed is ONE EXPERIENCE within the broader platform.

Do not architect the main menu, player profile, discovery system, or content model around RPGs alone.

==================================================
2. CORE PLATFORM METAPHOR
==================================================

The central product metaphor is:

INTELLIGENT TABLETOP
=
A digital tabletop on which many different games can be played.

The Grand Gaming Table V1 is the physical visual representation of that metaphor.

The table itself remains visually consistent.

What is placed upon the table changes depending on the game.

Examples:

RPG:
- dungeon
- terrain
- walls
- miniatures
- props

Strategy:
- world map
- armies
- territories
- markers

Card game:
- cards
- decks
- player hands
- tokens

Board game:
- board
- pieces
- cards
- resources

Economic game:
- properties
- money
- player pieces
- market elements

The platform should therefore be game-agnostic at the foundational level.

==================================================
3. DISCOVER-STYLE MAIN MENU
==================================================

The main menu should NOT be a traditional:

New Game
Load Game
Settings

launcher.

It should function more like a modern content discovery platform.

The design philosophy is inspired by the DISCOVER philosophy used by Fortnite, but Intelligent Tabletop must NOT copy Fortnite's branding or visual design.

We are borrowing the information architecture and discovery philosophy.

The principle is:

"Choosing what to play should feel like discovering an experience, not navigating a settings menu."

==================================================
4. PRIMARY NAVIGATION
==================================================

The intended top-level navigation is:

PLAY
BROWSE
LIBRARY
CREATE
PROFILE

Settings should remain accessible separately, either through Profile or a dedicated settings control.

Do not assume CREATE must be fully implemented immediately.

If the current project does not yet support game creation, preserve the navigation/design intent but mark CREATE as future functionality.

5. PLAY / DISCOVER HOME
==================================================

PLAY is the personalized home/discovery experience.

It should eventually include dynamic content rows such as:

- Continue Playing
- Recommended for You
- Featured Experiences
- New & Notable
- Popular
- Recently Played
- Great With Friends
- Game Types
- Curated collections

Do not make the homepage RPG-specific.

For example, Continue Playing could contain:

- an RPG campaign
- a strategy match
- a card game
- a board game

at the same time.

The home experience should adapt to the player's actual usage.

==================================================
6. EXPERIENCE CARDS
==================================================

Do NOT use "Adventure Card" as the universal content model.

The platform concept is:

EXPERIENCE CARD

An Experience represents a playable tabletop game or mode.

An Experience Card may contain:

- title
- artwork
- game type
- player count
- estimated session length
- genre
- tags
- difficulty
- multiplayer information
- status
- progress
- creator/developer
- rating/recommendation information where applicable

Examples:

"The Ruins of Ironwatch Keep"
- RPG
- 2–6 players
- Campaign

"Empires of Antiquity"
- Strategy
- 2–6 players
- 90–180 minutes

"Arcane Champions"
- Card Game
- 2–4 players
- Competitive

"World at War"
- Grand Strategy
- 2–6 players

"Merchant's Fortune"
- Economic Board Game
- 2–6 players

The same platform component should be able to represent all of these.

8. LIBRARY
==================================================

LIBRARY represents the player's personal collection.

It should eventually contain:

- Favorites

DISCOVER:

==================================================
10. PLAYER PROFILE
==================================================

Intelligent Tabletop needs a persistent PLAYER PROFILE.

This profile represents the player's identity across the entire platform.

It is NOT a character sheet.

It is NOT tied to one specific game.

The player profile may eventually contain:

- Display name
- Avatar
- Player identity
- Platform progression if introduced
- Games played
- Tables hosted
- Friends
- Groups
- Favorites
- Created experiences
- Recently played
- Statistics
- Preferred game types
- Achievements
- Earned titles
- Equipped title

The profile exists independently of any specific game.

A player can play:

- RPGs
- card games
- strategy games
- board games
- party games

and all of those activities contribute to their persistent platform identity where appropriate.

==================================================
11. PROFILE VS SETTINGS
==================================================

Keep these concepts separate.

PROFILE:
"Who am I on Intelligent Tabletop?"

SETTINGS:
"How does Intelligent Tabletop work for me?"

Settings can eventually include:

- Account
- Appearance
- Audio
- Accessibility
- Notifications
- Controls
- Gameplay preferences
- Privacy
- Multiplayer/online settings
- Data/storage

Do not mix these concepts into one giant profile screen.

==================================================
12. EARNED TITLE SYSTEM
==================================================

The player profile must eventually support a Destiny-style EARNED TITLE SYSTEM.

This is NOT a collectible badge/card system.

This is NOT simply XP progression.

The model is:

GAME / ACTIVITY
      ↓
OBJECTIVE SET
      ↓
COMPLETE REQUIRED OBJECTIVES
      ↓
EARN TITLE
      ↓
EQUIP TITLE
      ↓
DISPLAY TITLE ON PROFILE

A title represents an accomplishment.

Example:

CARDMASTER

The player completes a defined collection of objectives associated with card-game mastery.

Once the requirements are met:

TITLE UNLOCKED:
CARDMASTER

The player can equip it.

Their platform identity may then appear as:

Josh — Cardmaster

==================================================
13. TITLE OBJECTIVE / SEAL MODEL
==================================================

Each title should have an associated objective set.

A title may require the player to complete a number of defined accomplishments.

For example:

CARDMASTER

Possible objectives:

- Win a certain number of competitive card games
- Win using multiple deck archetypes
- Complete a difficult card challenge
- Reach a specified competitive tier
- Defeat different opponents
- Complete specific mastery challenges

The exact requirements are game-specific and should be defined by the individual Experience.

The platform should provide the generic framework for:

- title definition
- objective definition
- progress tracking
- completion
- unlocking
- equipping
- displaying

Do NOT implement arbitrary example requirements as permanent game rules.

==================================================
14. TITLE TYPES
==================================================

Titles may eventually exist at several scopes.

PLATFORM TITLES:
Earned through broad Intelligent Tabletop accomplishments.

GAME-TYPE TITLES:
Examples:

Cardmaster
Grand Strategist
Dungeon Delver
Board Veteran

GAME-SPECIFIC TITLES:
Defined by an individual Experience.

EVENT/SEASONAL TITLES:
Potential future support.

The system should not assume all titles belong to one game.

==================================================
15. TITLE DESIGN PRINCIPLE
==================================================

Titles should represent accomplishment.

Do not make them primarily purchasable cosmetics.

Their value comes from the fact that the player earned them.

A player may earn multiple titles but equip a selected title as their current identity.

The system should eventually allow players to view:

- earned titles
- locked titles
- objective requirements
- progress
- currently equipped title

==================================================
16. CROSS-GAME PLAYER IDENTITY
==================================================

This is a critical platform principle.

The player identity is persistent across Experiences.

For example:

PLAYER:
Josh

EQUIPPED TITLE:
Cardmaster

RECENTLY PLAYED:
- RPG
- Strategy
- Card Game

PROFILE:
- 42 games played
- 8 tables hosted
- 3 earned titles

The exact statistics are future implementation details.

The architectural principle is what matters:

THE PLAYER EXISTS ABOVE ANY INDIVIDUAL GAME.

The existing presentation direction remains LOCKED.

DISCOVER
    ↓

    ↓
LOBBY / TABLE
    ↓
GRAND GAMING TABLE
    ↓
ZOOM INTO TABLETOP
    ↓
GAMEPLAY

The tabletop itself changes according to the Experience.

Do not assume all Experiences use the RPG dungeon presentation.

==================================================
18. RPG CAMERA MODEL
==================================================

For the current RPG experience:

ZOOMED OUT:
- Grand Gaming Table is visible
- surrounding players/environment may eventually be visible
- dungeon exists on the tabletop

ZOOMED IN:
- table largely leaves the frame
- camera becomes a shared group tactical perspective
- players see the dungeon/map
- miniatures remain tabletop-scale

This is a shared group perspective.

It is NOT an individual character camera.

Do not build the RPG as a conventional character-centric third-person game.

==================================================
19. MINIATURE MODEL
==================================================

For the current RPG implementation:

Miniatures are static tabletop objects.

They:

- remain on circular bases
- have a defined position
- have a defined facing
- move as complete miniature objects
- do not currently require animation

The base is the gameplay anchor.

Future animation can exist independently:

Character Entity
    ↓
Gameplay Position
    ↓
Miniature Base
    ↓
Animated Visual

Animation belongs to rendering, not the rules engine.

This principle must remain intact.

22. DISCOVERY SHOULD BE CURATED
==================================================

We want the philosophy of large discovery platforms, but NOT an overwhelming wall of content.

The Intelligent Tabletop home page should eventually favor:

- strong featured content
- personalized recommendations
- useful horizontal rows
- clear categories
- concise metadata
- visual browsing
- easy continuation of existing games

Do not blindly reproduce Fortnite's number of rows or visual density.

Intelligent Tabletop should feel curated and premium.

INDIVIDUAL EXPERIENCES MAY HAVE THEIR OWN VISUAL IDENTITIES.

==================================================
FINAL PRODUCT PRINCIPLE
==================================================

The most important principle to preserve is:

INTELLIGENT TABLETOP IS THE TABLE.

The individual games are what we put on it.

The player is the persistent identity moving between those experiences.

The Discover system helps the player decide what to put on the table.

The Profile remembers who they are.

The Title system records what they have accomplished.

The Grand Gaming Table provides the physical metaphor.

The individual Experience provides the rules and visual world.

The architecture should preserve these boundaries.
