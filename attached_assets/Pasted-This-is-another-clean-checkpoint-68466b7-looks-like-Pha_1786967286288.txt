One thing I would fix before the next phase

The React closure concern is worth addressing before the system gets more complicated.

Right now:

afterPlayerAction()
    ↓
captures viewport from render
    ↓
calculates next viewport

With the current synchronous/simple behavior, it’s fine. But once we introduce large maps, more frequent viewport changes, and potentially transitions, there’s no reason to retain that theoretical stale-state window.

I’d make it:

setViewport(prev =>
  updateViewportForActor(
    prev,
    actorWx,
    actorWy,
    worldW,
    worldH
  )
)

That makes the viewport update explicitly dependent on the latest viewport state, rather than the render closure.

It’s a tiny change and gives us a cleaner foundation.
