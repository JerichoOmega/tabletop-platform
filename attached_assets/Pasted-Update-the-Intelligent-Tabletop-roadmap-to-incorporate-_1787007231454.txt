==================================================
1. CORE PLATFORM THESIS
==================================================

Intelligent Tabletop is NOT a general-purpose VTT, Tabletop Simulator clone, or open creator platform at launch.

The platform thesis is:

"Intelligent Tabletop is a curated online tabletop platform for friends who want to start quickly, play with confidence, and finish a great game on time."

The platform should provide:
- fast session discovery
- party/lobby flow
- clear game expectations
- deterministic rules
- guided onboarding
- automated bookkeeping
- persistent session/campaign state where appropriate
- AI assistance where it adds value
- reliable session closure
- multiple distinct tabletop games sharing platform infrastructure

The platform does NOT impose one universal session length.

Instead, every game has a GAME-SPECIFIC SESSION CONTRACT.

==================================================
2. SESSION CONTRACT SYSTEM
==================================================

Add a first-class platform concept called a Session Contract.

A Session Contract should define, at minimum:
- target duration
- expected duration range
- player count
- ideal player count
- setup/onboarding time
- expected downtime profile
- core gameplay loop
- closure condition
- pause/resume behavior
- reconnect behavior
- campaign/standalone status
- AI role
- complexity/learning profile
- accessibility expectations
- elimination policy where applicable

Duration must eventually be telemetry-backed rather than simply declared by content authors.

Track:
- party-ready → results-screen duration
- active play duration
- setup/onboarding duration
- waiting/downtime per player
- player-count-specific duration
- new-player vs experienced-group duration
- abandon rate
- completion rate
- rematch rate
- reconnect/pause behavior

The roadmap should treat trustworthy session duration as a platform-level quality metric.

Do NOT require every game to have the same duration.

Canonical initial targets:

RPG tabletop mode:
~60 minutes, approximately 50–70 minutes in practice.

3v1 Human DM:
~60–90 minutes.

Ages of Empire:
~120 minutes, with an approximate validated range around 100–135 minutes rather than an artificially exact two-hour promise.

Quick games:
~15–30 minutes.

Future games:
game-specific duration determined by their core loop.

The principle is:
"Finishable does not mean short."

==================================================
3. RPG PRODUCT DIRECTION
==================================================

The RPG must remain a STREAMLINED tabletop adventure, not a compressed D&D campaign.

Target approximately 60 minutes per mission.

The RPG should support:
- briefing
- quick loadout
- meaningful exploration
- social interaction
- environmental interaction
- natural-language player intent
- one meaningful approach decision
- one major optional objective or a small number of discoveries
- one micro-encounter OR one major tactical encounter
- occasionally a micro-encounter plus a major encounter
- meaningful consequences
- campaign persistence
- automated resolution and bookkeeping
- a clear ending

Do NOT allow the extra hour to become:
- open-ended roleplay
- extensive inventory management
- crafting/vendor loops
- huge spell lists
- dense character sheets
- long equipment optimization
- unlimited side quests
- arbitrary world expansion
- a traditional 2–4 hour D&D session

The guiding principle is:

"Players can change what happens, but cannot endlessly expand what the game is."

==================================================
4. RPG MISSION ARCHITECTURE
==================================================

Replace any roadmap language that treats a rigid scene count as the primary pacing mechanism.

The preferred architecture is:

MISSION CONTRACT + ESCALATION GRAPH

Mission Contract:
- primary objective
- stakes
- target duration
- known success/failure/retreat outcomes
- optional objective(s)
- closure conditions

Escalation Graph:
- finite authored state graph
- multiple approaches
- meaningful state transitions
- escalation
- commitment
- climax
- aftermath
- controlled convergence

Use BRAIDED BRANCHING rather than exponential branching.

Player choices should alter:
- routes
- encounter composition
- available allies
- resources
- information
- faction relationships
- threat state
- tactical conditions
- ending configuration

But branches should eventually reconnect to controlled campaign anchors.

Do NOT build an exponentially branching campaign tree.

Every mission must have a closure state:
- success
- success at cost
- partial success
- failure
- retreat

Failure is a valid campaign outcome, not a request to replay the same mission.

==================================================
5. RPG EXPLORATION
==================================================

Exploration should be a bounded systemic layer, not an infinite room simulator and not merely a menu.

Locations should contain a limited number of salient opportunities.

Use structured world tags such as:
- fragile
- flammable
- unstable
- concealed
- locked
- guarded
- holy
- flooded
- mechanical
- social

Natural language can combine existing capabilities and environmental tags.

The player should be able to say something unexpected.

However:

AI interprets intent.
Rules/content systems determine whether the action is supported.
Rules engine validates legality.
Game state executes the result.
AI narrates the validated result.

The AI must NEVER invent a mechanical capability simply because the player's wording sounds plausible.

Unsupported actions should receive constructive alternatives based on actual game state.

==================================================
6. EXISTING AI AUTHORITY MODEL MUST REMAIN CANONICAL
==================================================

Preserve and extend the architecture already proven in the RPG prototype:

Player Intent
→ Intent Interpreter
→ Proposed Action
→ Rules Validation
→ Game State Mutation
→ Resolution
→ UI Update
→ Session Log

The AI/natural-language layer must never directly mutate authoritative game state.

Traditional direct controls and AI-assisted/adventure controls must ultimately use the SAME underlying rules and execution functions.

The system already demonstrates this separation and must not regress it.

Future AI architecture should formalize:
- proposal schemas
- validation
- stale-state revalidation
- structured tool calls
- permissions
- audit logging
- prompt/version tracking
- AI cost controls
- failure handling
- deterministic fallback behavior

AI should be:
- intent parser
- narrator
- rules explainer
- continuity assistant
- recap generator
- encounter/complication recommender
- campaign chronicle assistant
- later, DM copilot

AI should NOT be:
- authoritative rules engine
- hidden state mutator
- unrestricted game master
- balance authority
- source of mechanical truth

Canonical principle:

"AI proposes. The rules engine decides. The world state persists. The table renders the result."

==================================================
7. RPG COMBAT PACING
==================================================

Combat is the most likely pacing bottleneck.

Design the roadmap around:
- approximately 3-player tactical parties
- approximately 3–5 rounds for a major encounter
- approximately 15–20 minutes for the main climax
- limited action vocabulary
- movement + major action + constrained reaction
- few but distinctive enemies
- clear enemy intent
- objective-based encounters
- automated math/status tracking
- fast resolution
- minimal downtime

Encounters should include objectives such as:
- rescue
- escape
- defend
- capture
- disrupt
- survive
- retrieve
- hold
- destroy

Do not make "kill every enemy" the default objective.

Allow:
- one major encounter
OR
- one short micro-encounter plus one major encounter

Do not build missions around two long conventional combats.

==================================================
8. RPG CHARACTER PROGRESSION
==================================================

Keep progression intentionally light.

Prefer:
- approximately six major progression milestones
- lightweight talent choices
- limited equipment slots
- mission-relevant loadouts
- a small number of relics or special tools
- faction/campaign rewards
- rapid post-mission upgrades

Avoid:
- giant skill trees
- huge spell lists
- inventory spreadsheets
- deep crafting economies
- lengthy vendor phases
- optimization-heavy builds

Returning players should be able to prepare a character quickly.

==================================================
9. CAMPAIGN DESIGN
==================================================

Campaigns are collections of FINISHABLE missions.

Recommended initial campaign structure:
- approximately 4–5 missions for the first vertical slice
- approximately 6–8 missions for a compact full campaign
- approximately 8–10 missions for a larger flagship campaign

Persistent state should use a constrained vocabulary:

- faction standing
- regional threat
- resources
- allies/assets
- scars/losses
- story keys
- route availability
- information discovered

Consequences must be visible when they matter.

Do not allow persistent flags to become invisible backend bookkeeping.

Campaigns should be BRAIDED rather than infinitely branching.

==================================================
10. AGES OF EMPIRE
==================================================

Ages of Empire is NOT subject to the RPG's 60-minute limit.

Canonical target:
approximately 120 minutes.

Design target:
approximately 100–135 minutes once telemetry validates actual play.

The game should be:
- a Risk-inspired territory strategy game
- with Civilization-style development influences
- four historical Ages
- finite rounds
- VP victory
- no player elimination
- compact map
- fast turns
- limited development
- meaningful diplomacy
- deterministic final round
- strong anti-cleanup mechanics

Recommended initial player count:
2–4.

Balance primarily for:
3–4 players.

Do NOT prioritize 5–6 players until actual telemetry proves the core game can support it.

==================================================
11. AGES OF EMPIRE STRUCTURE
==================================================

Target approximately 8 total rounds.

Approximately:
- 2 rounds Ancient
- 2 rounds Medieval
- 2 rounds Industrial
- 2 rounds Modern

Do not add an entirely new subsystem every Age.

Each Age should change the strategic question and value of the board.

Ancient:
- establish geographic/economic position

Medieval:
- borders, alliances, routes, regional power

Industrial:
- infrastructure, development, mobility, leverage

Modern:
- convert power into VP
- endgame objectives
- destabilization/endgame pressure

Use a compact development tableau rather than a Civilization-scale technology tree.

Target roughly:
6–10 meaningful development choices per player across the game.

Avoid:
- long prerequisite chains
- tiny percentage bonuses
- separate economic simulations
- research queues that take multiple rounds to become meaningful

==================================================
12. AGES OF EMPIRE ANTI-DOWNTIME SYSTEM
==================================================

The roadmap must explicitly include mechanisms for keeping a 120-minute game from becoming a four-hour game.

Investigate/implement:
- simultaneous planning
- limited strategic orders
- reveal/resolution phases
- concise conflict windows
- limited reaction windows
- automated scoring
- automated upkeep/reinforcement
- deterministic or low-variance combat
- strong board readability
- final-round trigger
- fixed round cap

The game must NOT rely on player elimination to end.

Victory should be VP-based.

Scoring should include more than raw territory:
- objectives
- infrastructure
- regional control
- age achievements
- strategic milestones

Prevent runaway leaders and cleanup without arbitrary rubber-banding.

==================================================
13. AGES OF EMPIRE DIPLOMACY
==================================================

Diplomacy should remain socially expressive but mechanically bounded.

Players may freely negotiate.

The game may optionally support structured diplomatic actions such as:
- temporary truce
- trade pact
- non-aggression agreement
- shared objective
- conditional support
- limited alliance

Structured agreements should have explicit duration and consequences.

Do not turn diplomacy into a complicated contract-management subsystem.

==================================================
14. 3v1 HUMAN DM MODE
==================================================

Keep 3v1 as a later mode.

Target:
approximately 60–90 minutes.

This is NOT "unrestricted D&D mode."

The human DM is a DIRECTOR operating within the game's contract.

The DM may:
- choose prepared scene packages
- alter revelation order
- roleplay NPCs
- select validated complications
- alter enemy tactics within rules
- select bounded objectives
- spend a finite director budget
- add a short optional scene
- ask AI for dialogue/continuity/pacing assistance

The DM may NOT:
- bypass the rules engine
- invent unsupported mechanics
- create multi-session subplots during a mission
- infinitely expand the map
- add unlimited encounters
- silently retcon state
- ignore closure conditions

Introduce a Director Budget containing bounded quantities of:
- major complications
- minor complications
- optional scenes/micro-encounters
- threat adjustments
- terrain twists

The DM dashboard should expose:
- mission state
- objectives
- active clocks
- director budget
- encounter budget
- player state
- pacing forecast
- unresolved mandatory beats
- AI pacing recommendations

3v1 should be added only after the standard RPG mission architecture is proven.

18. CREATOR / UGC ROADMAP
==================================================

Do NOT build an open creator marketplace at launch.

Stage the ecosystem:

Stage 1:
First-party games only.

Stage 2:
Curated external partners.

Stage 3:
Constrained creator tools based on approved:
- objectives
- actions
- components
- session contracts
- duration limits
- content schemas
- validation

Stage 4:
Marketplace/revenue sharing.

Stage 5:
Advanced creator scripting only if deterministic multiplayer, moderation, security, performance, IP, and discovery systems can support it.

The roadmap should explicitly reject:
- unrestricted scripting at launch
- arbitrary asset uploads at launch
- open UGC at launch
- AI-generated mechanics without validation

==================================================
19. AI PRODUCT POSITIONING
==================================================

Do not make "AI-powered" the primary consumer-facing identity.

The product should be marketed primarily as a great tabletop game/platform with intelligent assistance.

Internally, AI is strategically important.

Externally, the experience should communicate:
- adaptive
- intelligent
- responsive
- coherent
- rules-aware

rather than "the AI makes anything possible."

This is especially important because AI gameplay risks include:
- inconsistency
- hallucination
- latency
- privacy
- state/memory failures
- player distrust

The roadmap must therefore prioritize reliability and state coherence over generative novelty.

22. FUTURE-PROOFING RULES
==================================================

Add an explicit "Do Not Compromise" section to the roadmap.

The following are architectural/product constraints:

1. AI never becomes authoritative game-state mutation.
2. Game-specific rules remain game-specific.
3. Session length is game-specific.
4. Every game has a defined closure contract.
5. Failure is a valid game outcome.
6. Campaigns use bounded braided branching, not exponential branching.
7. Exploration is expressive but bounded.
8. Creator systems remain constrained until governance exists.
9. Multiplayer/platform infrastructure must not compromise deterministic game logic.
10. Telemetry must validate duration claims.
11. Replay/event history should remain possible because of authoritative state transitions.
12. Core games must remain playable without depending on generative AI availability.
13. No feature should be added solely because AI makes it technically possible.
14. The platform should optimize for satisfying completed sessions, not artificially maximizing session length.
15. Additional session time should buy more meaningful decisions, not more bookkeeping.
